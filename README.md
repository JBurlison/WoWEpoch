# My Epoch

Recap expansion (2026-11-03): 23 optional metrics now include personal survival, wallet/net gold, auctions, XP, completed quests, estimated distance, longest active session, loot quantities, roll wins and duel/battleground outcomes. Numbers use thousands separators. [Definitions, source evidence and validation](docs/recap-expanded-metrics.md) distinguish observed totals from missing/restricted history.

A character scrapbook for **WoW Forever**. Private specifications, implementation notes, prototypes, artwork originals and previews live in the ignored `docs/` and `design/` folders and can be maintained in a separate private repository. References to those folders below describe optional local development records; they are not required to run or package the addon.

Implementation is underway, not feature complete. The addon contains a persistent character store, canonical quest attempts/kills/credits, observations of quests, levels, accessible group chat and item receipts, wallet balances/deltas, observed active time, personal notes, restricted-scope recap calculations, and a two-page native book. Development data starts empty; browser sample history is never imported into the addon.

Open with `/myepoch` or `/epoch`. `/myepoch status` reports runtime build and capability checks. `/myepoch close` cancels automatic combat reopening; `/myepoch capture` requests a screenshot and saves its metadata. The Archive chapter controls book scale and opt-in combat closing. Notes save as typed into SavedVariables, which WoW writes at its normal reload/logout lifecycle.

The native book includes the shared illustration dialog, quest atlas, Journey map and per-character retention controls. All 1,309 planned illustrations are present. Remaining work includes large-history storage and recovery, quest eligibility and victim-specific credit, financial and crafting coverage, and released-client validation. Development build 0.2 adds quiet queued recap updates, per-character period/milestone navigation, unread indicators, stable notes and read/star state, persisted daily summaries, same-second milestone ordering, and indexed date queries. Repetitive activity is summarized without discarding source records; daily entries and source links are paginated. Local calendar tests cover 23/25-hour days. Quest membership gaps, delayed/ambiguous turn-ins and unavailable group identity are kept explicit.

Confirmed implementation policies: major profession milestones every 75 points and weapon-skill milestones every 25. Group sessions survive roster churn; a group identity observed in party events can preserve a session across reloads, with the unobserved interval retained as a gap. If identity continuity cannot be verified, a separate linked segment is labeled accordingly.

Development build 0.3 adds the FIFO cost-lot engine, integer-copper partial-stack allocations, dated returns, inventory coverage boundaries, unmatched-cost handling, and matched profit/margin/ROI calculations. The native Gold chapter has inclusive local-date pickers; today/yesterday/last 3/7/30/90 days, MTD/QTD/YTD, previous month and all-history presets; balance/income/spending/net charts; source filtering; and coverage-aware financial metrics. Graphs keep observation gaps visible and use a bounded texture pool. Zero-valued metric cards are omitted.

All date views use local time, as confirmed by the user. Wallet observations are polled during active collection, with separate baselines after interruptions. Quest reward evidence can produce an explicitly inferred source association; ambiguous evidence returns it to unknown. Vendor/auction cash movement, confirmed operating cash and transfers are separate. Hourly rates exclude recorded AFK and require matching observation coverage. The FIFO engine has fixture tests, but live purchase, sale, mail, trade and auction collectors have not yet been connected to its cost lots. This build must not be treated as complete automatic trading-profit capture.

## Development checks

Packaging does not require `docs/` or `design/`: the finished artwork stays in `MyEpoch/Media`, with its catalog and texture checksums recorded in `tools/art-release.json`. When editing artwork, restore the private sources at `design/`, run `python tools/build-art-catalog.py`, and include the updated catalog, release manifest and exported textures together. Packaging also checks the private source register when it is present. Quest source provenance remains tracked at `vendor/bundled-quest-source.json`. The requirements audit below needs the private design and documentation folders; ordinary packaging does not. The local update installer requires the machine-specific tracking file `.tools/installed-build.json`, which is also ignored.

```powershell
python -m venv .tools/venv
./.tools/venv/Scripts/python.exe -m pip install -r requirements-dev.txt
./.tools/venv/Scripts/python.exe tests/run.py
./.tools/venv/Scripts/python.exe tools/package.py
./.tools/venv/Scripts/python.exe tools/requirements-audit.py
./.tools/venv/Scripts/python.exe tools/install.py
```

Tests execute the actual Lua modules with **Lua 5.1**, including a strict frame/event test surface. They cover model invariants, persistence round trips, Lua syntax/TOC load order, localization, character isolation, book behavior at three screen sizes, observation gaps, queued recap updates, FIFO/returns/unknown costs, financial date controls and a 5,030-record archive fixture. A 20,000-point chart fixture checks bounded texture use. Mocked tests do not prove WoW rendering, protected execution, event order or secret-value semantics. The installer checks prior installed hashes, refuses unexpected edits and backs up replaced managed addon files; it never modifies SavedVariables.

The development ZIP has `MyEpoch/` at its root. Install only that folder in the Forever `Interface/AddOns` directory. No companion, network dependency, or sample data is needed by the addon. Back up SavedVariables through normal filesystem tools before testing new development builds; the addon does not manage files outside WoW's SavedVariables lifecycle.
